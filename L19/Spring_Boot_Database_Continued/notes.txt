Problems & Challenges with this code:
1. No id coming in the response on employee creation
2. Schema is not flexible, as in whenever we need to add a new column, we don't have to update the schema programatically
3. Even if we figure out a way to update the schema (i.e via alter table commands), we still need to update the entire code
to accomodate the new incoming field or the outgoing field (in case of dropping off a column)
4. The queries that we have been writing are difficult to scale (i.e when the data grows bigger, it will be difficult for us to manage all the sql queries ourself)

5. Error Prone -- we are converting from object --> relation (insert)
                  we are converting from relation --> object (select)

6. We are not sure that the queries we are writing are optimized...
