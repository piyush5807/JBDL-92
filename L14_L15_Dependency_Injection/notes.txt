
Spring boot has 2 main pillars

1. IOC - Inversion of Control

BeanFactory / Application Context ==>  IOC container

(synchronized (keyword) ==> critical section)

2. DI - Dependency Injection
Phenomenon to inject the dependency that is already created by spring boot

@AutoWired - used for dependency injection. DI is exhibited by @Autowired keyword.

Bean - Object created by spring boot during the application startup or otherwise as well and managed by spring boot itself.

DemoController - bean
DemoService - bean
String - bean


------------------------

Types of DI
1. Field Injection -

2. Constructor Injection -

3. Setter Injection - @Autowired annotation on top of setter function is mandatory whereas in constructor it's not mandatory


Field vs Constructor

Field injection always happen after the constructor is executed, so if we want to do something on the autowired object in the constructor,
we should avoid using field injection


Bean Scope - Every bean that is created by spring boot has a scope, by default it's singleton that means
spring boot will create only 1 instance of that bean and will use it for autowiring at multiple places.

Prototype - SB does not create an instance of this bean, as it is not singleton, infact it creates instances on need basis
i.e whenever some class auto wires a prototype scoped bean, SB will create an object for it.

@Qualifier - Annotation which is given on the consumption side (where the dependency needs to be injected to let SB know which dependency to inject)
@Primary - Annotation which is used on the production side (where we are defining the beans to let SB know which bean to prioritise during injection)
